# Spec: orders-service

## Purpose

HTTP API that accepts a beverage delivery order, stores it in PostgreSQL, and publishes `order.created`.

## Out of scope

- Fulfillment status. That lives in `fulfillment-service`.
- A transactional outbox worker. Publish happens after the insert. See failure behavior.
- A drink catalog. Any sku/name that passes validation is accepted. The web UI has a fixed menu.

## Runtime

- Node.js 22, TypeScript, Fastify, Zod, `pg`, AWS SDK v3 SNS client.
- Config from the environment: `DATABASE_URL`, `SNS_TOPIC_ARN`, optional `AWS_REGION` (default `us-east-1`), optional `AWS_ENDPOINT_URL` (LocalStack), `PORT` (default `3001`), `HOST` (default `0.0.0.0`), `LOG_LEVEL` (default `info`), `CORS_ORIGIN` (default: reflect the request origin).
- On startup, wait for PostgreSQL and apply migration `001_init` once, recorded in `schema_migrations`.
- Logs are structured JSON through Fastify/pino. A successful create logs `orderId`, `eventId`, and whether the call was a replay.

## HTTP

### `GET /health`

- `200` `{ "status": "ok", "service": "orders", "db": "up" }` when `SELECT 1` succeeds.
- `503` `{ "status": "degraded", "service": "orders", "db": "down" }` otherwise.

### `POST /orders`

Body (unknown fields rejected):

```json
{
  "customerName": "Ada Lovelace",
  "address": "1 Market St",
  "items": [{ "sku": "ESP", "name": "Espresso", "quantity": 2 }],
  "notes": "no sugar"
}
```

Validation:

- `customerName`: 1–80 characters, trimmed.
- `address`: 1–200 characters, trimmed.
- `items`: 1–20 entries. `sku` 1–40, `name` 1–80, `quantity` integer 1–50.
- `notes`: optional, trimmed, max 280. Empty becomes `null`.

Header `Idempotency-Key`: optional. When present, 1–80 characters from `[A-Za-z0-9._:-]`. When absent, the server generates a UUID, so each call without a key is a new order.

Responses:

- `201` the public order, header `idempotent-replayed: false`, when the row was inserted.
- `200` the same public order, header `idempotent-replayed: true`, when the key already exists.
- Both responses echo `Idempotency-Key`.
- `400` `{ "error": "validation_error", "details": [{ "path": "...", "message": "..." }] }`.
- `503` `{ "error": "event_publish_failed", "orderId": "...", "message": "..." }` when the row is saved and SNS publish fails. The client retries with the same key.

Public order:

```json
{
  "id": "uuid",
  "customerName": "Ada Lovelace",
  "address": "1 Market St",
  "items": [{ "sku": "ESP", "name": "Espresso", "quantity": 2 }],
  "notes": "no sugar",
  "createdAt": "2026-01-01T00:00:00.000Z"
}
```

`eventId`, `idempotencyKey`, and `eventPublishedAt` are not part of the public body.

### `GET /orders/:id`

- `200` public order.
- `400` when `id` is not a UUID.
- `404` `{ "error": "not_found" }`.

### `GET /orders?limit=`

- `200` `{ "orders": [ ...public orders, newest first ] }`.
- `limit` defaults to 20. It must be an integer from 1 to 100 or the response is `400`.

Unexpected errors return `500` `{ "error": "internal_error" }` and are logged. The client does not receive a stack trace.

## Data

Table `orders`:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid | Primary key, generated by the service. |
| `idempotency_key` | text | Unique. |
| `event_id` | uuid | Generated once, reused on publish retries. |
| `customer_name` | text | |
| `address` | text | |
| `items` | jsonb | |
| `notes` | text | Null when omitted. |
| `created_at` | timestamptz | Set by the service. |
| `event_published_at` | timestamptz | Null until SNS accepts the publish. |

Index `orders_created_at_idx` on `created_at DESC`.

A unique violation on `idempotency_key` is a lost race. The service loads the winning row and continues with the replay path.

## Publish

After the row exists, publish `order.created` as specified in `event-contract.md`. Then set `event_published_at`.

If `event_published_at` is already set, do not publish again.

If publish fails, leave `event_published_at` null and return `503`. The same key on the next call publishes the original `eventId` and does not insert another row.

This is a deliberate dual-write. A crash between insert and publish is recovered by the client retry. It is not an outbox. Do not add an outbox without updating this spec.

## Acceptance

- Creating an order returns `201`, persists the row, and publishes one event whose shape matches the fixture keys.
- The same `Idempotency-Key` returns `200` and does not publish a second event.
- A failed publish returns `503` with the saved `orderId`. The retry publishes once and returns `200`.
- Invalid bodies, bad keys, unknown ids, and bad `limit` values return the status codes above.
- `/health` reports the database.
- Tests cover the HTTP behavior with an in-memory repository. A PostgreSQL test runs when `DATABASE_URL` is set.
